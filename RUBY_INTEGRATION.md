# Ruby UI Integration for PRC-152 Radio Firmware

This document describes the experimental Ruby (mruby/c) UI layer for the PRC-152 radio firmware.

## Overview

The firmware now supports an optional Ruby-based UI layer using [mruby/c](https://github.com/mruby/mrubyc), a lightweight Ruby implementation designed for microcontrollers. This allows writing UI code in Ruby while keeping performance-critical hardware drivers in C/C++.

### Why Ruby?

- **Cleaner UI code** - Ruby's expressive syntax makes UI logic easier to read and maintain
- **Faster iteration** - Change UI without recompiling everything
- **Separation of concerns** - UI logic is cleanly separated from hardware drivers
- **Easier to extend** - Add new screens and menus with minimal boilerplate

### Memory Impact

| Component | Flash | RAM |
|-----------|-------|-----|
| mruby/c VM | ~200KB | ~40KB |
| Ruby bytecode | ~5-20KB | - |
| **Total overhead** | ~220KB | ~40KB |

ESP32-S2 has 4MB Flash and 320KB RAM - plenty of headroom.

## Prerequisites

### Install mruby compiler (mrbc)

The Ruby files must be compiled to bytecode before flashing to the device.

**macOS:**
```bash
brew install mruby
```

**Ubuntu/Debian:**
```bash
sudo apt install mruby
```

**From source:**
```bash
git clone https://github.com/mruby/mruby.git
cd mruby
make
# Add build/host/bin to PATH
```

Verify installation:
```bash
mrbc --version
```

## Project Structure

```
PRC152_PIO/
├── ruby/                    # Ruby source files
│   ├── main.rb              # Full UI application
│   └── demo.rb              # Simple demo/test
├── include/
│   ├── ruby_bindings.h      # C/Ruby interface header
│   └── ruby_bytecode_*.h    # Auto-generated bytecode (don't edit)
├── src/
│   ├── ruby_bindings.cpp    # C binding implementations
│   └── main.cpp             # Modified to support Ruby mode
└── compile_ruby.py          # Bytecode compiler script
```

## Enabling Ruby UI Mode

1. **Edit `src/main.cpp`** and uncomment the define:
   ```cpp
   #define RUBY_UI_ENABLED
   ```

2. **Build the project:**
   ```bash
   pio run
   ```

   The build will:
   - Compile Ruby files to bytecode via `compile_ruby.py`
   - Generate header files in `include/ruby_bytecode_*.h`
   - Build the firmware with Ruby support

3. **Flash and monitor:**
   ```bash
   pio run -t upload && pio device monitor
   ```

## Available Ruby Classes

### LCD

Controls the 128x32 monochrome display.

```ruby
$lcd = LCD.new

# Clear screen
$lcd.clear              # Clear everything
$lcd.clear(:edit_zone)  # Clear only edit area (rows 1-3)

# Text display
$lcd.text(x, y, "Hello", :small)   # 4x8 font
$lcd.text(x, y, "Hello", :medium)  # 6x8 font (default)
$lcd.text(x, y, "Hello", :large)   # 10x16 font
$lcd.text(x, y, "Hello", :medium, true)  # Inverted (highlighted)

# Widgets
$lcd.battery(percent)              # Battery indicator
$lcd.signal(level)                 # Signal strength bar
$lcd.volume(level)                 # Volume indicator (0-7)
$lcd.frequency(x, y, 145.500)      # Frequency display
$lcd.channel(x, y, 42)             # Channel number
$lcd.icon(x, y, icon_id)           # Display icon
$lcd.progress_bar(x, y, percent)   # Progress bar
$lcd.scrollbar(total, selected, per_page)  # Scrollbar
$lcd.contrast(level)               # Set contrast (0-6)
```

### Radio

Interface to the radio transceiver.

```ruby
$radio = Radio.new

# Get channel info (returns Hash)
chan = $radio.channel
chan[:number]    # Channel number (0-100)
chan[:rx_freq]   # RX frequency (e.g., 145.500)
chan[:tx_freq]   # TX frequency
chan[:name]      # Channel nickname
chan[:power]     # Power level

# Other properties
$radio.volume        # Current volume (0-7)
$radio.volume = 5    # Set volume
$radio.rssi          # Signal strength (0-100)
$radio.squelch       # Squelch level
$radio.battery       # Battery percentage
$radio.ptt?          # true if receiving, false if transmitting

# Send AT command to radio module
$radio.send_at("AT+DMOSETVOLUME=5")
```

### Event

Handle user input events.

```ruby
$event = Event.new

# Poll for events (non-blocking)
evt = $event.poll
if evt
  case evt[:type]
  when 1  # KEY_CLICK
    handle_click
  when 2  # KEY_LONG
    handle_long_press
  when 4  # ENCODER_CW
    handle_rotate_clockwise
  when 5  # ENCODER_CCW
    handle_rotate_counterclockwise
  when 6  # MATRIX_KEY
    handle_keypad(evt[:value])
  end
end
```

Event types:
- `1` - KEY_CLICK (encoder button click)
- `2` - KEY_LONG (encoder button long press)
- `3` - KEY_DOUBLE (double click)
- `4` - ENCODER_CW (rotate clockwise)
- `5` - ENCODER_CCW (rotate counter-clockwise)
- `6` - MATRIX_KEY (keypad press, value = key code)
- `7` - PTT_DOWN
- `8` - PTT_UP
- `9` - SQUELCH

### Timer

Time-related functions.

```ruby
$timer = Timer.new

$timer.millis        # Milliseconds since boot
$timer.delay(100)    # Delay 100ms (cooperative yield)
```

### System

System utilities.

```ruby
$system = System.new

$system.log("Debug message")  # Print to serial console
$system.free_memory           # Free heap in bytes
```

## Writing Ruby UI Code

### Basic Screen Pattern

```ruby
class MyScreen
  def initialize
    @position = 0
  end

  def render
    $lcd.clear(:edit_zone)
    $lcd.text(0, 1, "My Screen", :medium)
    $lcd.text(0, 2, "Position: #{@position}", :medium)
  end

  def on_event(evt)
    case evt[:type]
    when 4  # ENCODER_CW
      @position += 1
      render
    when 5  # ENCODER_CCW
      @position -= 1
      render
    end
  end
end
```

### Menu System

```ruby
class Menu
  def initialize(items)
    @items = items
    @position = 0
  end

  def render
    $lcd.clear(:edit_zone)
    3.times do |i|
      idx = @position + i
      break if idx >= @items.length
      selected = (i == 0)
      $lcd.text(0, i + 1, @items[idx], :medium, selected)
    end
    $lcd.scrollbar(@items.length, @position, 3)
  end

  def up
    @position = (@position - 1) % @items.length
    render
  end

  def down
    @position = (@position + 1) % @items.length
    render
  end
end
```

## Limitations

mruby/c is a subset of Ruby. Notable missing features:

- No `require` or `load` - all code compiled together
- No `eval` or `send` - no dynamic method calls
- No modules (only classes)
- No `method_missing`
- No regular expressions
- Limited standard library

For UI code, these limitations are rarely an issue.

## Development Workflow

1. Edit Ruby files in `ruby/` directory
2. Run `python compile_ruby.py` to test compilation
3. Build with `pio run`
4. Flash and test with `pio run -t upload && pio device monitor`

## Switching Between C and Ruby UI

The firmware supports both modes:

- **C mode (default):** Comment out `#define RUBY_UI_ENABLED` in `main.cpp`
- **Ruby mode:** Uncomment `#define RUBY_UI_ENABLED`

Both modes share the same hardware drivers and can coexist in the codebase.

## Extending the Bindings

To add new C functions accessible from Ruby, edit `src/ruby_bindings.cpp`:

```cpp
// 1. Define the C function
static void c_my_function(mrbc_vm *vm, mrbc_value v[], int argc) {
    int arg1 = mrbc_integer(v[1]);
    // Do something
    SET_INT_RETURN(result);
}

// 2. Register it in the appropriate class
static void register_my_class(void) {
    mrbc_class *cls = mrbc_define_class(0, "MyClass", mrbc_class_object);
    mrbc_define_method(0, cls, "my_function", c_my_function);
}

// 3. Call registration in ruby_init()
int ruby_init(void) {
    // ...
    register_my_class();
    // ...
}
```
